# Rustless 编译器设计教程：详细大纲（待审批）

本教程以 Rustless 的现有实现为学习对象，解释一个编译器怎样用清楚的数据结构表达程序，怎样把语法解释为语义，怎样逐步形成适于分析和执行的表示。贯穿全书的问题是：**一种设计如何把应当成立的关系表达清楚，并使后续修改能够沿着这些关系进行？**

本文件是正式撰写前的大纲。它规定章节、教学顺序、语言示例、实现摘录和图示；审批后再形成完整的 TeX 教程。当前核对基线为 Rustless 提交 `ac85604`，写作时将保留明确的源码出处，并重新核对可能变化的行号。

## 一、读者、范围与叙述方式

### 1. 读者需要知道什么

假定读者了解 C++ 的结构体、函数、容器和基本指针概念。`std::variant`、移动所有权、模板约束、Visitor、名字解析、类型判断、SSA、支配关系和 ABI 都会在首次使用时说明。Rustless 语法由示例逐步介绍；读者无需预先了解完整 Rust。

阅读后，读者应能从一段 Rustless 程序推导出 AST 的结构，解释一次语义判断需要哪些信息，阅读已有 IR，并为尚未完成的 lowering 和后端选择合理的表示与接口。

### 2. 已有实现与后续设计的范围

| 内容 | 教程中的位置与说明方式 |
| --- | --- |
| ANTLR 词法与语法分析、AstBuilder、类型安全 AST、分派与遍历 | 第一、二篇；阅读当前实现并解释设计理由 |
| 名字解析、语义类型、表达式检查、常量、结构体与方法、语义事实查询 | 第三篇；讲清已有规则，也分析需要完善的接口 |
| typed IR、IR Visitor、Builder、验证器、LLVM 文本输出、RV32 布局与内部 ABI 桥接 | 第四篇前半；阅读当前实现 |
| AST 到 IR 的完整 lowering、聚合操作、优化器、机器表示、寄存器分配、运行时连接 | 第四篇后半与第五篇；依据已有表示进行设计推导 |
| Rx-Compiler 的 lowering 与 RV32 后端 | 标为“参考实现”；用于阅读算法及比较表示方式 |

当前 Rustless 尚无完整源程序 lowering 和机器后端。`use`、生命周期与 `where` 的语法保留，也不等于完整模块解析或借用检查。教程将这些边界放在相应概念旁说明，避免读者把语法记录、语义判断和代码生成混为一谈。

### 3. 每章与每节的写法

每章开头有一份导读：先用容易理解的语言说明本章要解决的问题，再指出重要概念及与前后章的联系。正文小节采用以下推进顺序：

1. 给出一个具体问题和 Rustless 示例。
2. 说明要正确解释这段代码，必须保留或确定哪些信息。
3. 引入必要的概念、定义或判断规则。
4. 阅读项目的 C++ 摘录，追踪这些信息怎样得到表达。
5. 分析维护、运行代价和扩展上的收益与限制。
6. 用一个变式或反例检验理解，并引出下一小节。

这一路径借鉴概率论讲义从具体试验建立抽象模型的推进方式，以及 Visitor 教程从处理需求引入设计的顺序；用词保持专业、自然，不照搬其口语表达。[概率论讲义第一章](https://chihaozhang.com/teaching/Prob2026/lectures/lec1.html)、[Visitor 教程](https://awesome-embedded-learning-studio.github.io/Tutorial_AwesomeModernCPP/vol4-advanced/vol4-generics-patterns/16-visitor)。

每幅图之前先有说明句，明确它呈现哪一段文字中的哪一种关系；图后说明阅读重点。代码摘录前给出阅读任务，摘录后解释字段、控制过程及设计意义。真实实现、删节摘录、教学伪代码和建议接口分别标明，防止建议被误认为已有代码。

### 4. 如何讨论“优雅”

全书以五个可检查的问题组织设计取舍：结构是否直接表达语言概念；同一个决定是否有明确的归属；阶段之间是否传递足够的信息；修改一种结构时是否容易找到相关处理；表示与算法的代价是否可以解释和测量。

性能讨论分别考察对象大小、堆分配、访问局部性、分派、字符串与类型重复、查找复杂度及分析重算。没有测量依据时说明可能的收益与成本。不会把 variant、继承、arena、类型唯一化或更多中间层写成普遍最优的选择。

### 第 1 章　同一个程序，为什么需要不同表示

**导读。** 一段程序既是人能够阅读的文本，也是有层次的语法结构，还是将要执行的计算。本章沿着一个简单函数观察这些视角，说明编译器为何逐步改变表示。读者将在全书开始时明确每个阶段要回答的问题。

**小节安排。**

- **1.1 从一个计算开始。** 以 `a + b * c` 说明文本顺序、结构关系和计算依赖之间的区别。
- **1.2 词法、语法与语义。** 分别解释“有哪些词法单元”“如何组成程序”“名字与操作是否合法”；用语法正确但类型不相容的变式区分判断层次。
- **1.3 AST、语义事实、IR 与机器代码。** 展示各表示保留什么信息、明确什么关系；解释一个 AST 节点可以产生多条 IR 指令。
- **1.4 阶段之间需要传递什么。** 先引入源码位置、节点身份、声明身份、类型、转换和来源信息，后续章节再逐一展开。
- **1.5 用什么评价一种设计。** 将结构清晰、维护范围、扩展方向和运行代价落实到本章例子；提出后续章节共同使用的评价问题。

**Rustless 示例。** `fn calculate(a: i32, b: i32, c: i32) -> i32 { a + b * c }`；错误变式 `1 + true`。同一个合法函数将在第 3、7、10、14、17 章再次出现，每次只增加一种解释。

### 第 2 章　源文本、词法单元与诊断位置

**导读。** 编译器解释程序时，也必须向读者指出错误发生在哪里。本章说明源码如何被保存和切分，以及字符位置为什么不能简单等同于字节位置。读者将看到源码表示既服务于解析，也贯穿后续诊断。

- **2.3 空白、注释与非法词法单元。** 解释隐藏通道、嵌套块注释、未闭合注释和保留非法输入以产生诊断的理由。

### 第 3 章　从语法分析树到 AST

**导读。** 语法分析器形成的树忠实反映语法规则，但后续分析需要按语言概念组织的结构。本章比较两种树，并沿着优先级、结合性和后缀表达式阅读 AstBuilder。读者将学会根据构造过程判断最终 AST 的形状。

**小节安排。**

- **3.1 Parse tree 与 AST。** 对照语法规则层次与表达式概念，解释为何中间优先级规则不必成为 AST 节点；说明保留括号也可以是 AST 的合理选择。
- **3.2 优先级如何形成父子关系。** 从乘法、加法、比较和逻辑运算逐层解释 grammar；用两棵树比较有括号与无括号的表达式。
- **3.3 结合性与 fold_binary。** 阅读左折叠；说明赋值右侧递归及 cast 链。`a = b = 1` 只作为语法结构示例，其语义合法性另行判断。
- **3.4 后缀链怎样包裹已有表达式。** 追踪调用、方法、字段和索引的逐步构造；解释为什么每一步都接收前一步的 base。
- **3.5 块、分号和尾表达式。** 说明 parser 上下文如何转为 Stmt 序列与可选 tail，完整判断留到第 6、12 章。

- **3.7 普通、条件与语句表达式。** 说明条件中未加界定的结构体构造、条件中的 break 操作数及以块开头的语句所产生的歧义；阅读三类规则如何被统一构成同样的 AST 载荷，避免把语法上下文差异传播为三套语义节点。

## 第二篇　用类型组织 AST

本篇将构树所需的关系转化为数据结构，随后研究如何在稳定的结构上增加处理过程。节点设计、分派和遍历依次展开，使 Visitor 的讨论建立在真实语言结构上。

### 第 4 章　节点身份、具体载荷与所有权

**导读。** 二元表达式需要两个操作数，返回表达式可以没有返回值，函数调用需要一个有序参数序列。本章从这些区别出发，说明共同信息、具体形状和子节点所有权怎样分工。读者将理解类型安全首先是在结构层面表达必要的关系。

**小节安排。**

- **4.1 相同拼写与不同出现。** 用两次 `1 + 2` 区分结构相同、位置不同和身份不同；说明 NodeId 的有效范围及与 SymbolId 的区别。
- **4.2 Node 与 owner。** 解释 `Expr : Node` 共享身份和范围；`Expr` 拥有 `Data`，`BinaryExpr` 描述具体语法。普通 Function 自身同时承担这两项职责。
- **4.3 从通用字段集合到 variant。** 以早期 `Kind/text/operands/flag` 作为历史对照，列出无意义字段组合，推导命名字段与活动载荷。
- **4.4 必需、可选与有序子结构。** 解释 `Box<T>`、`optional<Box<T>>` 和 `vector<Box<T>>`，分别对应语法要求；区分“没有节点”与 Unit 节点。这里的 C++ Box 用于拥有 AST 子节点，与源语言运行时容器 Box 分别定义。
- **4.5 递归类型与移动所有权。** 阅读 Box 构造、删除器和移动；解释不完整类型问题、删除器成本及 moved-from 对象的限制。
- **4.6 只读发布与可构造性。** 说明 `unique_ptr<const Crate>` 的发布方式、const 访问传播，以及公开字段和手工构造仍需满足的约束。
- **4.7 存储方案的取舍。** 讨论逐节点分配、variant 最大载荷、字符串和 vector 分配；比较 arena、索引节点和紧凑数组的可能方向，不作未测量的性能结论。

**Rustless 示例。** 两个相同二元表达式、`return` 与 `return 3`、零参数与多参数调用、`if` 的可选 else。错误 `1 + true` 用于说明结构合法仍需要语义判断。

**实现摘录。** A06—A08：`Id<Tag>/Node/Box`、`BinaryExpr/CallExpr/ReturnExpr`、`Expr::Data`、前端只读结果。

### 第 5 章　名字、类型语法与声明的组织

**导读。** 名字不仅出现在变量中，也组成路径、类型、导入和声明。它们有相似的拼写，却承担不同职责。本章说明 AST 怎样保留这些差别，并组织函数、结构体和实现块，为名字解析和类型解释提供清楚的输入。

**小节安排。**

- **5.1 Identifier、Binding 与 Mutability。** 区分名字、生命周期名和绑定；说明 `mut` 应出现在所属结构中。
- **5.2 路径按段保存。** 阅读 `Path/PathSegment/GenericArgument`；区分 `self`、`Self` 与普通标识符，说明泛型实参属于具体路径段。
- **5.3 五种类型语法。** 依次讲 UnitType、PathType、ReferenceType、ArrayType、ParenType；说明数组长度仍是表达式，引用的生命周期与可变性属于相应层。
- **5.4 函数签名与接收者。** 解释普通 Parameter、ValueSelf、ReferenceSelf、可选返回注解与函数体的分离。
- **5.5 结构体字段、常量与 derive。** 区分声明字段与初始化字段；解释属性与 DeriveKind 的记录方式。
- **5.6 Impl 与源码顺序。** 阅读混合 ImplMember 序列，说明成员函数与常量为何保留原顺序；解释 Crate 与 Item 的层次。
- **5.7 use 是一棵共享前缀的树。** 讲 NameImport、GlobImport、GroupImport、路径根、self/super/crate、普通 alias 与 `_`。
- **5.8 生命周期参数与 where。** 讲 LifetimeParameter、两类 WherePredicate 和可选约束；明确现有泛型形参是生命周期形参，语法保留的范围与语义处理的范围分别说明。

### 第 18 章　聚合值、调用与运行时操作的转换

**导读。** 数组、结构体、Box 和 Vec 不能全部当作一个标量处理。本章围绕构造、传递、复制和比较推导它们的转换方式，并将内建操作接到明确的运行时函数。读者将理解“表示为地址”为什么没有抹去源语言的内容语义。

本章属于**后续设计推导**；当前布局与 ABI 是已实现基础，完整聚合 lowering 与运行时连接尚未完成。

**小节安排。**

- **18.3 结构体字段初始化。** 按语言求值顺序计算，按声明布局写入；缺失/重复字段已经由语义检查拒绝。

- **18.5 Box 与 Vec 的对象表示。** 分配、元素地址、长度/容量、扩容与移除；运行时接口需要遵循元素类型和布局。

- **18.7 helper 的生成与复用。** 以具体类型为键缓存 clone/eq 等辅助函数；递归 helper 先登记再生成，避免无限递归。

## 第五篇　由计算走向机器

本篇属于后续设计方向。优化首先受到语言语义与 IR 不变量的约束；机器后端再受到指令、寄存器、内存与调用规则的约束。两类约束分开讲解，最后在完整输出路线中汇合。

### 第 19 章　优化为何正确：行为、分析与变换

**导读。** 指令更少并不自动意味着程序更好：输出、调用、内存和错误行为都可能因此改变。本章从简单变换出发，说明怎样判断优化合法，怎样把分析与变换分开。读者将理解清楚的语义和表示为什么是优化的基础。

**小节安排。**

- **19.1 可观察行为。** 以返回结果、输入输出、内存变化和规定的错误为依据解释等价；对照删除纯计算与删除读取输入的调用。
- **19.2 源语义与 IR 运算语义。** 讲溢出、除法、移位、poison 和立即未定义行为的区别；lowering 必须先表达规定行为。
- **19.3 最小优化集合。** 逐例介绍常量折叠、无用结果删除、分支简化、不可达块删除与冗余复制；说明无用结果不等于无副作用。
- **19.4 内存效果与别名。** 区分读、写、调用、可能失败和可投机执行；当前 has_side_effects 的简单分类不能独自证明任意重排。
- **19.5 分析与变换分离。** 讲 def/use、CFG、支配及活跃性，分析的复用、失效与重算；推导小型 pass 接口。
- **19.6 栈槽提升到 SSA。** 说明 mem2reg、Phi 插入与地址逃逸；比较先生成清楚的 load/store 与直接构造 SSA 的复杂度。
- **19.7 变换保持不变量。** 讲修改边后更新 Phi、删除定义后更新使用、验证前后 IR；用独立行为对照检验语义。
- **19.8 优化范围的选择。** 比较实现少量算法用于学习，与使用 LLVM 已有优化流程；依据目标而非层数决定设计。

**Rustless 示例。** `let x = 1 + 2; printInt(x);`；`let x = getInt(); let y = x * 0;`；包含副作用 RHS 的短路式；可提升局部变量与被借用变量的对照。

### 第 20 章　机器表示、Phi 消除与寄存器分配

**导读。** IR 可以创建许多值，机器却只有有限寄存器，某些操作还需要多条指令。本章说明机器表示如何承接 IR，随后由 Phi 消除和活跃变量分析推导寄存器分配。读者将看到目标约束为什么需要新的表示层。

**小节安排。**

- **20.1 从 IR 操作到机器操作。** 比较一对一和一对多选择；讲 RV32IM 目标、立即数范围、大偏移与 bool 的规范化。
- **20.2 机器操作数与身份。** 推导虚拟寄存器、物理寄存器、立即数、栈槽、符号与标签的具体类型；比较参考项目的表示与当前 AST/IR 原则。
- **20.3 Phi 变为边上的复制。** incoming 转为对应边的赋值，解释 critical edge 和拆边。
- **20.4 并行复制与循环。** 追踪两个寄存器交换、临时值和栈槽；讲复制合并与分配顺序的联系，避免把 Phi 串行执行。
- **20.5 活跃变量的固定点。** 定义 use/def、live-in/live-out，手工推导一个有回边的 CFG；解释集合如何稳定。
- **20.6 干涉与寄存器分配。** 从重叠活跃关系推导约束图，比较图着色和线性扫描的复杂度、效果与实现负担。
- **20.7 spill 与重新插入读写。** 说明溢出是位置变化，仍要保留原值；讨论使用频率、循环代价和额外临时寄存器。
- **20.8 调用约束。** 讲调用破坏、预分配参数、保留寄存器及跨调用活跃值；连接下一章的具体调用约定。
- **20.9 机器验证与输出。** 检查物理位置、合法操作数、分支目标和栈槽；指出汇编字符串不应承担全部机器语义。

**实现摘录。** R03—R05：Rx-Compiler 的 MachineInstruction、select、liveness、allocate 和并行复制。Rustless 尚无这些模块，推荐表示与参考算法分别标注。

### 第 21 章　栈帧、平台 ABI、运行时与输出路线

### 第 22 章　检验设计承诺，并有依据地扩展

**导读。** 清楚的设计不仅要能解释正常程序，也要能够指出不合法的结构，并让新增能力有明确位置。本章归纳各阶段需要检验的关系，再通过一个扩展示例追踪修改范围。读者将学会把正确性、维护和扩展性联系起来评价实现。

### 2. 图示的制作原则

前文已经为每张拟议图给出图前说明。正式绘制时：

- 树形关系使用节点与边，所有权、可选边和序列具有固定图例。
- 分派与方法解释使用调用路径或步骤图；头文件关系使用依赖图。
- 类型、符号和事实对应使用并列结构与明确身份连线。
- 分支、循环、支配与 Phi 使用 CFG，数据输入标在对应边上。
- 字节布局与栈帧使用按比例分区，空隙明确标注为 padding 或保留区域。
- 遍历、调用保存和并行复制使用时间线或逐步状态图。
- 扩展方向、语法覆盖和设计取舍适合表格时使用表格，不强行改成树图。

图中的颜色服务于关系，并有文字或线型辅助；箭头含义每图明确。不会用一套箭头混合表示 include、拥有、引用、执行和数据依赖。
